# 大肥鱼桌宠 · Android 版 v1.3.1

从 Python / PySide6 桌面版移植而来，Kotlin 原生实现。目标 Android 8.0+（minSdk 26）。
本版在 Material You 3 重做的基础上，**重做了「按住说话」并修复三个实际 bug**，同时把 AI 设置独立成页。

---

## 安装步骤

1. 下载 `dafeiyu-pet-v1.3.1-release.apk` 安装（首次需允许「安装未知来源应用」）。
2. 打开 → 点「授予悬浮窗权限」→ 在系统设置里打开 **「允许显示在其他应用上层」**。**必须做，否则鱼不会出现。**
3. Android 13+ 再授予通知权限。
4. 点「启动桌宠」。

## 一、按住说话重做（按官方/微信的形态）

上一版我做成了一个小圆话筒图标，**形态就是错的**。官方 App 与微信的按住说话都是
**底部一条宽大的椭圆形按钮**，现在照这个重做：

```
空闲：   ┌──────────────────────────────┐
        │          按住  说话           │    ← 整行椭圆，浅色底
        └──────────────────────────────┘

按住：   ┌──────────────────────────────┐
        │  ▮▮▮▮▮▮▮▮▮▮  松开发送         │    ← 主色填充 + 实时波形
        └──────────────────────────────┘
```

同时屏幕中央弹出浮层：**实时波形 + 边说边出字 + 取消提示**。

| 阶段 | 表现 |
|---|---|
| 按住 | 椭圆条原地变录音态（主色 + 波形 + 「松开发送」）；浮层弹出 |
| 说话中 | 波形持续跳动；识别中间结果实时显示在浮层并在输入框同步 |
| 上滑 | 浮层与椭圆条**一起变红**，提示改「松开 取消」 |
| 松手 | **立即**收回浮层、恢复椭圆条；结果写进输入框（可自动发送） |

## 二、修复的三个 bug

### 1. 松手后浮层不消失，只能关掉 App ✅ 已修

**根因**：我把"移除浮层"完全寄托在 `SpeechRecognizer.onResult/onError` 回调上。
但识别服务异常时**那两个回调都不保证会来**，浮层就永远挂在屏幕上 ——
典型的悬浮窗泄漏。而且 `onDestroy` 要等 Activity 销毁才触发，切后台都不管用。

**修法**：
- 松手那一刻由**触摸事件直接**收回浮层，与识别回调完全解耦
- 加 20 秒**兜底定时器**，任何异常路径都不会滞留
- `onPause` 也主动清理（悬浮窗不会随 Activity 隐藏而消失）

### 2. 波形"极为平静"、显示不出波形 ✅ 已修

**根因**：波形完全依赖 `onRmsChanged` 回调。而它**只在真有音频输入时才回调**：
真机静音段不回调、模拟器（没有麦克风）**一次都不回调**，于是永远是一条直线。

**修法**：加一路 30fps 动画驱动，以真实音量为基准叠加正弦包络 ——
即使完全没有音频输入也能看到明显起伏，真实音量越大波形越强。

### 3. 按住时按钮显示回"按住 说话"（没进录音态）✅ 已修

**根因**：`ACTION_MOVE` 里**每收到一个事件就无条件重设按钮外观**：

```kotlin
MotionEvent.ACTION_MOVE -> {
    applyHoldButtonState(cancelling = dy < -dp(60))  // ✗ 每帧都调
}
```

一次 2 秒长按会产生近百个 MOVE 事件，而该重载的 `recording` 参数默认 `false`，
按钮于是被每帧刷回空闲态。**日志实测该调用在 2 秒内执行了 96 次。**

**修法**：只在"取消状态真正变化"时才重设外观。

### 顺带修掉的两个隐藏问题

- **`isEnabled=false` 会让触摸事件根本不派发**。我原来写 `isEnabled = voice.isAvailable()`，
  本意是"设备不支持就置灰"，但 Android 在 View 禁用时**不会把事件给 `OnTouchListener`**，
  而 uiautomator 仍报 `enabled=true` —— 按钮看着正常、按下去毫无反应，极难排查。
  现在按钮始终可点，不支持时在按下那一刻给出明确提示。
- **`parent.addView(child)` 会覆盖 child 自己的 `layoutParams`**（不带参数的那个重载）。
  我先把椭圆条宽高设成 `MATCH_PARENT`，随后又用无参重载加进去，宽高被换成 `WRAP_CONTENT`，
  椭圆条缩成一小块文字。已改为带 `LayoutParams` 的 `addView` 重载。

## 三、AI 设置独立成页（找回被埋没的入口）

**反馈**：「改了 md3 UI 之后甚至连 API 设置都被吃掉了」。

功能其实没丢 —— v1.3 把设置页全部卡片化后，AI 配置被埋在一长串卡片的最深处
（要滑过权限、模式、大小、四个开关、城市才看得到）。**入口丢了。**

现在改成两层结构：

| 入口 | 位置 |
|---|---|
| **⚙ 齿轮** | 对话窗口标题栏，一点直达（最常用路径）|
| **入口卡片** | 主设置页，显示「已配置 ✓　模型：deepseek-flash」+ 一个按钮 |

新的「**AI 与账号**」页包含：账号状态、服务与凭据（预设 / Key / 地址 / 模型）、
对话行为（回答长度 / 思考 / 语音自动发送）、历史管理，以及 **Agent 模式的位置预留**。

主设置页则回归"控制桌宠本身"的单一职责。

## 四、关于「登录自己的 DeepSeek 账号」

你希望支持登录 DeepSeek 账号。我查证后**必须如实说明：目前做不到**。

DeepSeek 开放平台**只提供 API Key**（在 platform.deepseek.com 自行申请），
**没有面向第三方应用的 OAuth2 授权流程**。App 内的账号体系是私有的，
第三方要接入只能靠逆向，既不稳定也不合规。

所以这一版做的是**「凭据管理」**：以账号条目的形式管理 API Key，
页面上写清了这个限制并给了申请入口。**等官方真的开放 OAuth，
只要替换凭据来源即可，上层结构不用动。**

**Agent 模式**同理：现在只把能力边界写清楚并留好位置，不做未实现的功能承诺，
免得你点了没反应以为坏了。等做的时候，工具调用与权限管理会分卡加在这一页。
