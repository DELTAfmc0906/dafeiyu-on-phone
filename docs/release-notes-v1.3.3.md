# 大肥鱼桌宠 · Android 版 v1.3.3

从 Python / PySide6 桌面版移植而来，Kotlin 原生实现。目标 Android 8.0+（minSdk 26）。

**本版修复了「按住说话的波浪图松手后仍漂浮、根本消不掉」的严重 bug。**

---

## 安装步骤

1. 下载 `dafeiyu-pet-v1.3.3-release.apk` 安装（首次需允许「安装未知来源应用」）。
2. 打开 → 点「授予悬浮窗权限」→ 在系统设置里打开 **「允许显示在其他应用上层」**。
3. Android 13+ 再授予通知权限。
4. 点「启动桌宠」。

## 一、波浪图为什么会「根本消不掉」

用户反馈：

> "那个按住说话的波浪线图样依然在松手之后漂浮，根本消不掉"

**这是悬浮窗泄漏。** 查代码发现旧实现有三处叠加的缺陷：

### 缺陷 1：`addView` 失败被静默吞掉，却仍当成功

```kotlin
runCatching { windowManager.addView(column, params) }  // 失败被吞
root = column                                          // 却无条件赋值
```

如果 `addView` 失败，`root` 会指向一个**从未 attach 到窗口**的视图。
之后对它调 `removeView` 必然抛异常。

### 缺陷 2：`dismiss()` 先清引用，再吞掉失败

```kotlin
fun dismiss() {
    main.removeCallbacks(safetyDismiss)            // ← 一进来就取消了兜底
    val v = root ?: return
    root = null                                    // ← 先清引用
    runCatching { windowManager.removeView(v) }    // ← 失败又被吞
}
```

`removeView` 一旦失败，**屏幕上的视图就再没有任何引用能操作它** ——
而兜底定时器已被自己取消。于是永久漂浮，只能杀进程。

### 缺陷 3：连续按下会覆盖引用

```kotlin
voiceOverlay = VoiceOverlay(context).also { it.show() }   // 直接覆盖旧引用
```

用户在上一轮没结束时再按下（快速连按），旧浮层的引用就被覆盖，
**再也没人能收掉它**。

> 模拟器上没复现，是因为它的 `removeView` 一次就成功。
> MIUI 这类 ROM 对悬浮窗管控更严，失败概率高得多。

---

## 二、修复方式：把「保证消失」做成结构性能力

不是补一个 `dismiss` 调用，而是改了生命周期管理方式。

### 1. 摘除成功才解除登记

每个浮层都登记在一张**静态登记表**里，**只有在确认从 WindowManager 摘除之后
才解除登记**。这样即使某次 `removeView` 失败，登记表仍然持有引用，
稍后还能继续重试 —— 旧代码失败即彻底失联。

### 2. `removeView` 失败会升级重试

普通 `removeView` 失败时，改用 `removeViewImmediate` 再试一次
（某些 ROM 在视图有未完成布局事务时会拒绝普通摘除）。

### 3. 应用级心跳回收（最后一道保险）

`Application` 启动时开启一个 1.5 秒的心跳，扫描登记表：

| 情况 | 处理 |
|---|---|
| 超过展示期还没收 | 尝试摘除 |
| 处于「摘除失败」状态 | 用更强的方式重试 |
| 连续失败超过 5 秒 | 放弃重试（防无限耗电） |

心跳跑在**应用进程**里，与任何界面生命周期解耦 ——
这样即使对话界面早就销毁了，遗留的浮层依然会被收掉。

### 4. 补齐三个泄漏入口

| 入口 | 处理 |
|---|---|
| 松手 | 由触摸事件直接摘除（不等识别回调）|
| 切后台 / 退出界面 | `onPause` / `onDestroy` 调 `sweepAll()` 全量清扫 |
| **快速连按** | 建新浮层前先收掉旧的 |
| 兜底超时 | 20 秒 → **收紧到 12 秒**（挂着 20 秒太久）|

## 三、实测

| 测试场景 | 结果 |
|---|---|
| 基线窗口数 | 3 |
| 普通长按 → 松手 | 3 ✓ 无残留 |
| **快速连按 5 次**（旧代码必泄漏） | 3 ✓ 无泄漏 |
| **按住时直接切后台** | 3 ✓ 浮层已回收 |
| 崩溃检查 | ✓ 无 |

> ⚠️ **仍需真机确认**：模拟器的 `removeView` 一次就成功，
> 无法复现 MIUI 上的失败路径。修复针对的正是"摘除失败"这一情形，
> 但要在小米手机上才能验证到实际效果。
> 本版有应用级心跳兜底，**即使真机上摘除失败，最长 12 秒也会被强制回收**，
> 不会再出现"只能杀 App"的情况。
